# 不同仓库类型的模块划分示例

同一份引擎 + 数据 schema，套到不同类型的仓库时，泳道 / 模块命名 / 连线颜色
会跟着变。下面给 4 个具体例子，每个都列出"识别方法 + 典型模块"。

## 1 · AI Agent Skill

特征：有 `SKILL.md` / `AGENTS.md` / `CLAUDE.md` 作为规则源；输出是某种能力
（生成图表 / 文档 / 代码 / 视频等）；有模板/资源库。

**典型泳道**：`输入 / 规范层 / 资源层 / Token / 组装 / 质检`

## 2 · CLI 工具

特征：有 `bin/` 或 `cli/` 入口；命令分组；配置文件 / schema 解析层。

**典型泳道**：
```
输入层        → 命令解析 / 参数 schema / 环境变量
规范与配置    → 默认值 / 配置文件 / 校验规则
资源层        → 模板 / 示例 / fixture / 数据集
核心逻辑      → 各子命令 / handler / transformer
输出与适配    → formatter / printer / exporter
质检与测试    → 单测 / 集成测 / lint
```

参考案例（假设的）：
- 输入：U1 命令行 args
- 规范：D1 配置 schema
- 资源：R1 内置模板 / R2 示例配置
- 核心：M1 handle-foo / M2 handle-bar
- 输出：F1 JSON formatter / F2 table printer
- 质检：Q1 unit / Q2 e2e

## 3 · 前端框架 / UI 库

特征：`src/components/` `src/hooks/` `src/utils/`；构建配置；主题系统。

**典型泳道**：
```
入口层        → 公开 API / 入口组件 / 类型导出
主题与 Token  → 设计 token / 主题切换 / 暗色适配
组件层        → 原子 / 分子 / 有机体（按层级）
工具与 hook   → hooks / utils / 适配器
构建与发布    → rollup / vite / 打包 / changelog
测试          → 单元 / 视觉回归 / e2e
```

## 4 · Python / Rust 通用库

特征：`src/` + `tests/` + `docs/`；公开 API；类型定义。

**典型泳道**：
```
公开 API      → 顶层导出 / 类型签名 / 主要 class
核心模块      → 子模块 / 算法实现
基础设施      → 错误处理 / 配置 / 上下文
适配层        → IO / 序列化 / 协议
测试与基准    → 单测 / 集成测 / bench
文档与示例    → docs / examples / tutorial
```

## 怎么识别泳道

按"数据流向"切：

1. **入口**在哪？ → 输入层
2. **规则 / 决策**在哪？ → 规范层
3. **被引用的资源**在哪？ → 资源层
4. **风格 / 配置**在哪？ → Token 层
5. **真正的"做事"**在哪？ → 组装/核心层
6. **怎么验证做对了**？ → 质检层

每层通常 1–6 个模块；总数以读图时无需频繁搜索为准。

## 怎么识别连线

读 3–5 个核心文件的 import / require / include 关系，画出引用图：

- **主流程**：控制流主线（输入 → 规则 → 资源 → 组装 → 输出）
- **Token 注入**：风格 / 配置 → 产物
- **参考同步**：模板副本与正本
- **质检回环**：产物 → 校验 → 反馈

连线通常控制在 10–25 条。少不代表一定遗漏，多也不代表更完整；只保留有仓库证据且有助于理解架构的关系。
